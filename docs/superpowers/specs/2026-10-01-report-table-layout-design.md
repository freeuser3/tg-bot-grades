# Отчёт об успеваемости: исправление раскладки таблицы

Дата: 2026-10-01
Модуль: `renderer.py` → `_render_report_table`
Статус: утверждён (design approved)

## Проблема

Кнопка «📄 Отчёт об успеваемости» (`bot.py:96` → `send_report`) отдаёт PNG,
который строится функцией `_render_report_table` (`renderer.py:281`).
Измерения на синтетических данных (сентябрь 2026, 14 предметов, 22 учебных дня)
показали четыре независимых дефекта.

### Дефект 1 — теряются предметы (потеря данных)

`renderer.py:306` использует переменную цикла `day` после его завершения:

```python
for day, mark in subject.marks.items():
    key = (day.year, day.month)
    month_map.setdefault(key, {"days": set(), "subjects": []})
    month_map[key]["days"].add(day)
if subject.subject not in month_map[(day.year, day.month)]["subjects"]:   # ← day утекла
    month_map[(day.year, day.month)]["subjects"].append(subject.subject)
```

`day` после цикла — последний ключ `subject.marks`, поэтому предмет
регистрируется только в месяце своей последней оценки.

Проверено на отчёте с Sept+Oct+Nov:

```
 9.2026: дней=2  предметов=ПУСТО
10.2026: дней=2  предметов=ПУСТО
11.2026: дней=2  предметов=['Алгебра']
ожидалось: 09 -> [Алгебра, Литература], 10 -> [Алгебра], 11 -> [Алгебра]
```

На триместре карточки сентября и октября рисуются вообще без строк предметов:
все их оценки невидимы.

### Дефект 2 — сетка дат выходит за карточку (потеря данных)

`col_w = 40` (`renderer.py:291`) фиксирован и не зависит от числа дней.

```
доступно для дат: 286px  =  7 колонок по 40px
сентябрь:          22 дня  =  880px
```

Цикл отрисовки (`renderer.py:377-392`) не обрезает по границам карточки.
Результат на одной картинке:

- нарисовано ~102 кружка из 308 — **около двух третей оценок обрезано краем холста**;
- начиная с x=546 колонки дат затирают заголовки и значения «Ср.» и «Итог»
  (39711 посторонних пикселей в зоне x 560..688);
- 5337 пикселей нарисовано правее края карточки.

### Дефект 3 — обрезка названий предметов

`subj_w = 210` (`renderer.py:292`), а самое длинное название в реальном наборе
«Вероятность и статистика» — 229.5px при шрифте NotoSans-Regular 18px.
`_truncate_text` (`renderer.py:256`) многоточие добавляет корректно — проблема
в ширине колонки, а не в алгоритме.

### Дефект 4 — колонка «Итог» съедает место

`final_w = 52` (`renderer.py:294`) плюс заголовок «Итог» (`renderer.py:363`)
и значения (`renderer.py:398-401`). По решению владельца продукта колонка
удаляется: она дублирует то, что видно по сетке дат, и стоит 52px из 308px
сетки.

## Ограничения Telegram

Проверено по документации Bot API (`SendPhotoParams`; подтверждено тремя
независимыми источниками):

- сумма ширины и высоты ≤ **10000 px**;
- отношение сторон ≤ **20**;
- файл ≤ 10 MB.

При `W = 720` высота ограничена **9280px**.

Ограничение «авто-сжатие до 2560px по длинной стороне» **подтвердить не удалось**,
поэтому дизайн не полагается на него.

При недельных блоках (кружок 26px, строка 40px, 14 предметов) блок равен
656px, месяц — 5 блоков, триместр — 15 блоков:

```
15 * 656 + 316 = 10156px  +  720  =  10876  > 10000   ❌ sendPhoto вернёт 400
```

Вывод: триместр обязан отправляться несколькими картинками.

## Решение

Отчёт рендерится **по одной картинке на месяц** и отправляется несколькими
сообщениями подряд. Внутри месяца даты разбиты на блоки по ISO-неделям,
поэтому в строке не бывает больше 5 колонок дат и колонка остаётся широкой.

Принятые решения владельцем продукта:

| Решение | Выбор |
|---|---|
| Разбивка дат | блоки по ISO-неделям |
| Формат шапки даты | две строки: день недели + число |
| Формат вывода | одна картинка на месяц |

## Архитектура

Пять единиц, у каждой одна задача. Первые две — чистые функции без Pillow,
тестируются без рендера.

```
_group_by_month(report) -> OrderedDict[(year, month)] -> MonthData
    Grouping report.subjects by month. Pure data, no Pillow.

_week_blocks(days: list[date]) -> list[list[date]]
    Split dates into ISO-week blocks. Pure data, no Pillow.

_render_month(report, year, month, data, font_dir, *, with_header: bool) -> Image
    Draws all week blocks of one month. One month = one image.

render_report_images(report, font_dir=None) -> list[bytes]
    Public entry point. Returns one PNG per month, in chronological order.

bot.py:send_report
    Sends each returned PNG as a separate photo.
```

`MonthData` — словарь с ключами `days` (отсортированный `list[date]`) и
`subjects` (отсортированный `list[str]`).

Публичная функция `render_report_image` **удаляется**. Она возвращала один
`bytes`; новая возвращает список, а поведение «первая картинка» не имеет
смысла — на триместре это молча теряло бы два месяца. Обновляются
`tests/test_renderer.py` и `bot.py:11,58`.

## Раскладка

Одна картинка = один месяц = последовательность карточек-блоков.

```
W               720
padding          32
card_pad         24
subj_w          240     # «Вероятность и статистика» = 229.5px → без обрезки
avg_w            52     # колонка «Ср.»
final_w           0     # колонка «Итог» удалена
grid_w          308     # 608 - 240 - 8 - 52
col_w       min(56, grid_w // days_in_block)
mark_size   min(26, col_w - 12)
row_h       mark_size + 14
```

`col_w` считается по самому длинному блоку месяца, чтобы все блоки месяца
имели одинаковую ширину колонки — иначе блоки разъедутся по вертикали.

Так как блоки строятся только по будним дням (оценок в выходные нет),
`days_in_block ≤ 5`, а `308 // 5 = 61`, поэтому `col_w` всегда равен 56.
Формула с `min` — страховка на случай нестандартных данных (например,
ежегодный зачёт в субботу даст блок из 6-7 дней и `col_w` 44-51).

`_week_blocks` вызывается **внутри месяца**, на уже отфильтрованном списке
дней этого месяца. Поэтому блок никогда не пересекает границу месяца:
ISO-неделя 31 октября — 6 ноября даст два блока («28–31 окт.» и «1–5 нояб.»),
а не один. Заголовок карточки всегда внутри одного месяца.

`_truncate_text` остаётся как страховка на случай названия длиннее 232px,
но на текущем наборе предметов не срабатывает.

### Шапка даты — две строки

```
  Ср        ← NotoSans-Bold 14px, #8a94a8
  18        ← NotoSans-Bold 18px, #2c5aa0
```

Обе строки центрируются в колонке. Размеры шрифтов фиксированы и не зависят
от `col_w`: при минимально возможном `col_w = 44` строка «Ср» занимает 22px
и число «18» — 21px, то есть обе помещаются с запасом.

### Заголовок карточки-блока

Диапазон дат блока и месяц: `«1–4 сент.»`, `«7–11 сент.»`.
Одна карточка = одна неделя, поэтому перечисление дней не нужно.

### Титул и метаданные

Рисуются только на первой картинке (`with_header=True`), чтобы не
дублировать на каждом месяце:

- заголовок `Отчёт об успеваемости` (NotoSans-Bold 26px, `#1c3d6e`);
- метастрока `{term} · {start} — {end}` (NotoSans-Regular 14px, `#5a6478`).

На второй и последующих картинках вместо титула рисуется компактная
метка месяца (`Сентябрь 2026`, NotoSans-Bold 20px) — иначе три похожие
картинки неотличимы в чате.

## Поток данных

```
bot.py:on_report_button
  → send_report
      → grades.fetch_report()               → StudentTotalReport
      → renderer.render_report_images(report) → [png_sep, png_oct, png_nov]
      → для каждого png: message.answer_photo(BufferedInputFile(...))
```

Порядок месяцев — хронологический: ключи `OrderedDict` сортируются перед
рендером, чтобы порядок не зависел от порядка предметов в отчёте.

## Обработка ошибок

- `report.subjects` пуст или нет ни одной оценки → `render_report_images`
  возвращает `[]`; `send_report` отдаёт «За период оценок нет»
  (текущее поведение `bot.py:60`, без изменений).
- Месяц без оценок не попадает в результат вообще: он не создаёт ключ в
  `_group_by_month`.
- В месяце 1 блок → картинка из одной карточки. Допустимо.
- Исключения `fetch_report` не меняются: `bot.py:53-56` уже ловит и
  показывает текст ошибки.
- Жёсткой проверки суммы размеров в проде нет: она живёт в тестах как
  регрессия. Если у школьника окажется 25 предметов, месяц превысит 9280px
  и `sendPhoto` вернёт 400 — это видно по тексту ошибки Telegram.

Тесты 3 и 4 — главные: они ловят исходную причину, а не симптом.

## Известный риск

Если Telegram сжимает фото по длинной стороне до 2560px, месяц в 3425px
уменьшится примерно на четверть, и шрифт 18px станет ~13px. Это ограничение
документацией не подтверждено. **Проверка на реальном телефоне обязательна
до приёмки.**

Откат, если текст окажется нечитаемым: ужать кружки и строки —
`mark_size` 26 → 22 **и** `row_h = mark_size + 14` → `mark_size + 10`,
после чего вернуть одну картинку на весь триместр:

```
block_h = 48 + 40 + 8 + 14 * 32 = 544
15 * 544 + 316 = 8476px  +  720  =  9196  ≤ 10000   ✅
```

При `row_h = mark_size + 14` откат не помещается: `9316 + 720 > 10000`.
Поэтому ужимать нужно и кружок, и отбивку строки — иначе откат снова не
отправится. `bot.py` при откате сводится к одному `answer_photo`.
